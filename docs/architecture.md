# 产品与架构

回线首先解决跨过多次窗口切换后，回到被打断的任务。临时插曲可能涉及聊天、浏览器和表格，顺序循环会让用户重新识别窗口。产品的主入口是当前屏幕上的浮窗，默认聚焦搜索框并选中一个目标，常见路径只需呼出和回车。需要明确保留恢复顺序时，可以在离开前用全局快捷键把窗口压入复工栈。

| 场景 | 最短路径 | 失败时 |
| --- | --- | --- |
| 回复、查询后回到原工作 | 全局快捷键 → 回车 | 没有符合时长门槛的建议时，预选最近可返回的窗口 |
| 多扇窗口标题相近 | 呼出 → 输入应用或标题 → 方向键 → 回车 | 保留查询，显示空结果或切换失败 |
| 预知会被连续打断 | 每次离开前留线 → 浮窗切到复工栈 → 回车 | 目标失效时保留栈顶，可在工作台移除 |
| 想控制记录与后台行为 | 托盘暂停，或打开工作台设置 | 快捷键被占用时可在设置中换键 |

## 实现

- `NativeDesktop` 用前台 WinEvent 和低频校验跟踪窗口。每个目标同时验证 HWND、PID 与每次运行生成的窗口属性，避免句柄复用后切错窗口。空闲超过两分钟或休眠后结束上个记录段。
- `Trail` 以单调时钟管理近期轨迹和检查点。浮窗按最近一次访问对窗口去重，终点在最近 15 分钟且停留至少 45 秒的建议排在前面。目标通过 Windows 规则激活，并在确认同一窗口到达前台后出栈。
- 主窗口使用 WinUI 3。浮窗与工作台共享一个 HWND 和状态，切换到浮窗时调整大小、置顶并从任务栏及 Alt+Tab 隐藏。失焦将收起浮窗。托盘通过 Windows Shell 通知图标提供恢复入口，手动重开应用由单实例信号唤回工作台。
- 本地 JSON 只保留设置。登录启动由当前用户的 Windows 启动项执行 `Backthread.exe --background`。卸载会移除该启动项。
- 更新检查只访问 GitHub Releases 的 `latest` API，使用版本号比较并匹配本项目的 Windows x64 安装包。下载由浏览器打开。Actions 构建完成后发布安装包和 SHA-256 文件。
